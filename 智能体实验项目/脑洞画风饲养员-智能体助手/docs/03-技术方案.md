# 技术方案

## 1. 总体架构

项目刻意保持为单个 `index.html`，没有构建步骤、包管理器和运行时依赖。代码内部按职责分为四层：

| 层 | 职责 | 主要实现 |
| --- | --- | --- |
| 视图层 | 四个工作台的 DOM 渲染 | `viewFeed / viewIdea / viewLibrary / viewStudio` |
| 交互层 | 事件绑定、状态切换、提示反馈 | `bindFeed / bindIdea / bindLibrary / bindStudio` |
| 分析层 | 像素采样、聚类、描述器、提示词组装 | `analyzeFiles / kmeans / describe / composePrompt` |
| 存储层 | 画风资产的读写 | `store`（`localStorage`） |

这种结构的取舍很明确：以可移植、可离线、可审阅为第一优先级，牺牲了工程化拆分与可测试性。

## 2. 文件与体积

| 文件 | 体积 | 说明 |
| --- | --- | --- |
| `index.html` | 约 56 KB | HTML + CSS + JavaScript 全量内联 |
| 其中脚本 | 约 39 KB | 无压缩、无混淆 |

未使用任何 CDN、外部字体、远程图片或第三方 JavaScript 库。

## 3. 画风萃取算法

### 3.1 采样

1. `FileReader` 读取用户选择的图片为 DataURL。
2. `Image` 解码后绘制到 72×72 的离屏 `canvas`。
3. 逐像素读取 RGBA，跳过 alpha 小于 200 的像素。
4. 每张图最多贡献 5,184 个采样点；8 张图上限约 41,472 点。

### 3.2 主色板：k-means

- 聚类数 `k = 5`，迭代 14 次。
- 初始质心按采样序列等距取点，避免完全随机导致结果抖动。
- 距离度量为 RGB 空间的欧氏距离平方。
- 每轮按最近质心归并并更新均值。
- 结束后统计各簇样本数，按样本数降序输出 5 个十六进制颜色。

选择 RGB 而不是 Lab，是为了在无依赖条件下保持实现短小；代价是感知均匀性不如 Lab/CIEDE2000。

### 3.3 统计指标

对每个采样点计算 HSL 与相对亮度：

```
L = (max(R,G,B) + min(R,G,B)) / 2
S = (max - min) / (1 - |2L - 1|)
Y = 0.2126R + 0.7152G + 0.0722B      （R,G,B 归一化到 0..1）
```

汇总得到：

| 指标 | 定义 |
| --- | --- |
| `avgL` | 所有采样点 L 的均值 |
| `avgS` | 所有采样点 S 的均值 |
| `contrast` | 所有采样点 Y 的标准差 |
| `warm` | 色相在 320°–360° 或 0°–70° 且 S > 0.08 的像素数 |
| `cool` | 色相在 165°–285° 且 S > 0.08 的像素数 |
| `domHue` | 主色（样本数最多）的色相名称 |

### 3.4 描述器阈值

统计值到中文描述的映射如下，阈值写在 `describe()` 中，可审阅、可调整：

| 维度 | 阈值 | 输出 |
| --- | --- | --- |
| 明度 | `avgL < 0.30` | 低照度暗调 |
|  | `0.30 – 0.48` | 沉稳中低调 |
|  | `0.48 – 0.66` | 柔和中间调 |
|  | `≥ 0.66` | 明亮高调 |
| 饱和 | `avgS < 0.16` | 近中性低饱和 |
|  | `0.16 – 0.38` | 中等饱和 |
|  | `0.38 – 0.60` | 饱和明快 |
|  | `≥ 0.60` | 浓烈高饱和 |
| 冷暖 | `warm > cool × 1.25` | 整体偏暖 |
|  | `cool > warm × 1.25` | 整体偏冷 |
|  | 其余 | 冷暖对比 |
| 反差 | `contrast < 0.11` | 低反差 |
|  | `0.11 – 0.19` | 中等反差 |
|  | `≥ 0.19` | 强反差 |

### 3.5 已知局限

- 无法从像素判断材质与笔触，因此「胶片颗粒 / 水彩晕染 / 3D 渲染」等标签由用户手动选择。
- 无法判断画面语义（人物、场景、物体），因此不做自动内容识别。
- 极端纯色图会导致 k-means 出现空簇，代码已对空簇做保护，但色板会出现重复色。

## 4. 提示词组装

`composePrompt()` 按固定字段输出：

```
风格命名：
风格范式：
光影关系：
色调质感：
场景氛围：
画面主体：      （作品工坊传入）
使用用途：      （作品工坊传入）
画面比例：

成片提示词：风格 + 光影 + 反差 + 质感 + 主体 + 氛围 + 比例。
```

结构对应课程中强调的「风格 + 主体 + 场景 + 动作/情绪 + 构图 + 光线 + 画质 + 尺寸」，其中场景与构图由脑洞孵化阶段补齐。

## 5. 预览画布

作品工坊的预览不是占位图，而是按画风色板程序生成的抽象画面：

1. 以首、中、尾三色建立线性渐变底。
2. 用 `mulberry32` 伪随机数生成 16 个径向渐变光斑。
3. 叠加暗角。
4. 叠加像素级噪点模拟颗粒。
5. 画布宽高由所选比例决定（760 / ratio）。

同一个 `seed` 会得到同一张预览；点击「刷新预览」推进种子，得到同色系的新构图。

## 6. 脑洞孵化

使用输入文本与情绪标签拼接后的 FNV-1a 哈希作为种子，对五个词池做确定性抽样：

- 场景池 12 条
- 动作池 10 条
- 情绪池 8 条
- 构图池 8 条
- 光线池 6 条

同一输入得到同一组结果，便于复现与截图；不同输入产生明显差异。

## 7. 数据持久化

- 键名：`ndhf.styles.v1`
- 存储：`localStorage`
- 上限：最多保留 40 条画风档案
- 参考图：以 260px 长边、JPEG 质量 0.58 压缩为 DataURL，降低体积
- 写入失败（隐私模式、配额不足）时静默降级为内存态，不阻塞使用

## 8. 兼容性与性能

| 项目 | 结论 |
| --- | --- |
| 浏览器 | Edge / Chrome / 其他 Chromium 内核浏览器 |
| 协议 | `file://` 与 `http(s)://` 均可运行 |
| 依赖 | 无 |
| 萃取耗时 | 3 张 900×600 参考图在测试机上为亚秒级 |
| 首屏 | 无网络请求，打开即用 |
